# Ideation: Video Performance Signals for Bettors

## Codebase Context

**Project:** Virality — Next.js 16 / React 19 / TypeScript prediction market where users bet YES/NO on whether YouTube/TikTok videos hit a view-count milestone within a time window. LMSR pricing, Drizzle + Neon Postgres.

**Relevant infrastructure:**
- `GET /api/admin/video-stats` — returns viewCount, likeCount, categoryId, publishedAt
- `POST /api/admin/market-suggestion` — calls Claude LLM with channel avg views + subscriber count to generate market parameters
- `calibration.ts` — confidence score: `(1 − stdDev/mean of recent views) × ageScore × 100`
- `VideoStatsChart.tsx`, `LiveEngagementStats.tsx` — existing display primitives
- TikTok polling cron + oracle for live engagement tracking; LMSR price encodes community consensus

**The gap:** Users see a video, a milestone threshold, and a YES/NO LMSR price. They have no context for whether the milestone is easy or hard for this creator, where the video's velocity sits relative to the creator's norm, or what historical hit rates look like.

**Past learnings:**
- LLM calibration: never percentile framing in prompts; inject server-computed projections as explicit multipliers
- YouTube API silent field drops: always update the `fields=` projection string
- Neon timestamps: retrieve as epoch ms (`EXTRACT(EPOCH FROM col)::bigint * 1000`)
- BigInt: always `BigInt(stats.viewCount)` not raw JS number

## Ranked Ideas

### 1. Velocity Decay Clock
**Description:** Below the current view count, show the velocity required to hit the milestone from today vs. the video's current rolling pace. E.g., "Needs 209K views/day. Current 7-day avg: 41K/day." Updates every poll cycle.
**Rationale:** Directly answers "is this video on pace?" — requires only current poll data and milestone target, no historical corpus.
**Downsides:** Misleading if polling is infrequent; early vs. late window pacing isn't linear.
**Confidence:** 92%
**Complexity:** Low
**Status:** Unexplored

### 2. Milestone Sanity Meter
**Description:** Shows where the milestone sits relative to this creator's own view distribution, drawn from channel stats already fetched (avg views, stdDev). E.g., "This milestone is 4.7× this creator's avg — a top 8% performance for this channel." Always shows N.
**Rationale:** `calibration.ts` already computes stdDev/mean. Exposes that to users for the first time. Uses YouTube channel data at creation — no resolved Virality history needed.
**Downsides:** Channel avg skewed by outliers; denominator must be visible.
**Confidence:** 88%
**Complexity:** Low
**Status:** Unexplored

### 3. Creator Baseline Card
**Description:** A collapsible panel auto-populated at market creation showing the creator's median view trajectory at 24h / 72h / 7d across their last ~10 videos, with the current video's live count plotted against it. Verdict: "Ahead of pace / On pace / Behind pace."
**Rationale:** Collapses the manual tab-switching users do today. One extra YouTube API call at creation. `VideoStatsChart.tsx` is already the rendering primitive. Requires no Virality resolved history.
**Downsides:** "Last 10 videos" arbitrary; users may not open panel; trajectory data incomplete until a few polling cycles in.
**Confidence:** 86%
**Complexity:** Medium
**Status:** Explored — brainstorm started 2026-04-13

### 4. Milestone Feasibility Band
**Description:** Color-coded traffic light beneath milestone: GREEN (< 1.5× channel median), YELLOW (1.5–3×), RED (> 3×). Pure arithmetic — milestone ÷ channel_median_views. No LLM, no resolved history.
**Rationale:** Casual users who won't parse a percentile will read a traffic light. Builds on data already returned by video-stats API.
**Downsides:** Thresholds arbitrary until empirically validated; oversimplifies distribution.
**Confidence:** 83%
**Complexity:** Low
**Status:** Unexplored

### 5. LLM Briefing Card
**Description:** 2–3 sentence natural language summary generated by Claude at market creation, cached statically. Fed structured inputs: channel avg views, stdDev, subscriber count, milestone, time window, categoryId, milestone multiplier, velocity band. Never percentile framing — inject server-computed projections as explicit multipliers.
**Rationale:** Lowers expertise barrier without dumbing down market mechanics. Follows past LLM calibration learnings.
**Downsides:** Adds latency at creation; quality depends on prompt discipline.
**Confidence:** 81%
**Complexity:** Medium
**Status:** Unexplored

### 6. Pre-Bet Projection Tooltip
**Description:** On hover/tap of YES or NO: "On current pace → ~[X] views by deadline. Milestone: [Y]. Model: ~[Z]% — Market: [P]%." Shows the gap between velocity-implied probability and LMSR crowd price.
**Rationale:** The arbitrage signal — gap between trajectory and crowd. Requires only velocity + milestone math, no cold start.
**Downsides:** Probability conversion must be labeled as rough estimate; works better for TikTok than early-window YouTube.
**Confidence:** 78%
**Complexity:** Medium
**Status:** Unexplored

## Honorable Mentions (deferred — needs platform data)

- **Prior Market Hit Rate** — "creator hits milestone in 7/11 past Virality markets." Highest-value signal once data exists. Build infrastructure now; surface in UI when N ≥ 3 resolved markets per creator.
- **Liquidity Depth + Slippage Preview** — pure LMSR math. Useful for larger bettors; lower priority until meaningful trade volume.
